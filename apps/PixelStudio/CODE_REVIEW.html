一、问题列表（按严重程度排序）

中 · 已修复 FIX

#1 Swift 6 严格并发：PhotoKit 回调捕获非 Sendable 的 View

位置：Views/ExportSheet.swift · saveToPhotos(url:)

原实现用 PHPhotoLibrary.requestAuthorization(for:_:) 与 performChanges(_:completionHandler:) 的闭包回调。这两个回调在 iOS SDK 中被标注 @Sendable，而闭包内为更新 @State saveResult 捕获了 self （ExportSheet 是非 Sendable 的 View）。在 README 声明的 Swift 6 语言模式 下，这会产生「capture of 'self' with non-Sendable type ... in a @Sendable closure」诊断。

影响：严格并发模式下编译报错 / 警告；保存到相册路径不达标。

低 · 观察项（未改） NOTE

#2 EditorViewModel.isProUnlocked 非 @Published 的弱响应

该属性为普通 var，在 EditorView.onAppear / onChange 中赋值。付费墙的 限制判定（addLayer/addFrame 等）在动作触发时读取，逻辑正确。唯一边界：图层面板 sheet 打开期间 用户完成购买，底部「免费版上限」文案不会即时刷新。属极小概率 UI 滞后，非功能缺陷。

建议（非必须）：如需严格响应，可改为 @Published var isProUnlocked。 遵循「精准改动」原则未擅自更改。

低 · 观察项（未删） NOTE

#3 PixelBuffer 内的未使用绘制原语

drawLine、drawRect、fillRect 未被调用—— ViewModel 用自带的 paintLine/paintRect/stamp（含镜像+笔刷）实现绘制， floodFill 仍在使用。属审查前已存在的死代码，按要求保留不删，仅提示。

二、修复方式

#1 改用 async PhotoKit API

以单个继承 View 主线程隔离的 Task { } 包裹 await requestAuthorization(for:) 与 try await performChanges { }。变更块仅捕获 Sendable 的 url，不再捕获 self；saveResult 在 Task 恢复后于主线程直接赋值，无需 MainActor.run 桥接。

  • 消除非 Sendable 捕获 → 满足 Swift 6 严格并发。
  • 错误经 do/catch 统一回写本地化文案，逻辑与原行为等价。
  • 本地化键 export.photos.denied / saved / failed 维持不变（中英文均已存在）。
