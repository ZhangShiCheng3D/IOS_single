一、发现并修复的问题

高已修复本地化键缺失，英文环境显示中文

Views/MoreView.swift:78 中 subtitle: "语音、字号、通知与购买" 作为 LocalizedStringKey 使用，但该键在 zh-Hans.lproj 与 en.lproj 两份 Localizable.strings 中均不存在。后果：英文环境下「设置」卡片副标题直接回退显示中文原文。

修复：已向两份字符串表补齐该键 （中文恒等映射；英文译为 "Voice, text size, notifications & purchase"）。 全量复核后这是唯一缺失的本地化键，其余 130+ 键中英齐全一致。

中已修复Info.plist 设备能力架构错误

Info.plist 的 UIRequiredDeviceCapabilities 声明为 armv7（32 位）。而本应用最低系统为 iOS 17，所有支持设备均为 64 位，正确值应为 arm64。错误的 32 位能力声明在提交时可能被拒或导致设备兼容判定异常。

修复：armv7 → arm64。

中已修复缺少出口合规声明键

Info.plist 未声明 ITSAppUsesNonExemptEncryption。 本应用纯本地、不含非豁免加密，缺此键会导致每次 TestFlight/提交都被追问加密合规。

修复：新增 ITSAppUsesNonExemptEncryption = false。

中已修复缺失 StoreKit 本地测试配置文件

CLAUDE.md 与 README.md 的集成步骤均要求创建 StoreKit 配置文件，但仓库中不存在 *.storekit。缺失时模拟器内 Product.products(for:) 取不到商品，付费墙「立即解锁」按钮恒为禁用，无法本地走通购买/恢复流程。

修复：新建 SeniorHelper.storekit，含与代码 PurchaseManager.unlockProductID 完全一致的非消耗型产品 com.seniorhelper.unlock.lifetime，并配中英本地化文案。

三、剩余风险与建议（需业务侧决策，未改动）

建议占位 URL 待替换

PaywallView.swift 与 SettingsView.swift 中隐私政策 / 支持 / 帮助链接为 https://example.com/... 占位。需替换为真实地址后方可过审 （README 上架清单已列明，属业务内容，故未代改）。

提示Swift 6 严格并发（complete 模式）

CameraManager / NotificationManager 等非 Sendable 类在 DispatchQueue.async / Task 中捕获 self。 在默认 Swift 5 语言模式下编译通过；若将 Build Setting 切到 Swift Language Version = 6 且开启 complete 并发检查，会产生告警/报错。 届时建议给 AVFoundation 管理器标注 @unchecked Sendable 或收敛到单一 actor。 因当前无法在本环境编译验证，为避免引入不可控改动，本项未做修改，仅记录。

提示通知撤销使用硬编码上限

NotificationManager.cancel(for:) 以 0..<20 枚举标识符撤销旧通知。 当前单条计划提醒数远小于 20，安全；若未来放开提醒次数上限，需同步调整。

提示AppIcon 未放置实际图片

Assets.xcassets/AppIcon.appiconset 仅有 1024×1024 槽位，未关联图片文件。 不影响编译，上架前需补图。
